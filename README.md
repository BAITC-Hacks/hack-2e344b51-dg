# 🏙️ Аким на 5 часов

AI-симулятор управления городом: одинаковый виртуальный бюджет, пять управленческих
решений по транспорту, экологии, соцсфере, безопасности и городским сервисам —
и итоговый **Astana Quality of Life Score** с объяснением, что сработало и какие
риски остались.

## Проблема

Развитие города требует одновременного учёта нескольких направлений при ограниченном
бюджете. Симулятор даёт возможность быстро проиграть разные сценарии распределения
бюджета и увидеть их влияние на качество городской среды — без реальных последствий.

## Архитектура

```
┌──────────────┐      HTTP JSON      ┌──────────────────────────┐
│  Frontend     │ ──────────────────▶ │  FastAPI backend           │
│  (HTML/JS)    │ ◀────────────────── │                            │
└──────────────┘                     │  ┌──────────────────────┐  │
                                      │  │ engine/ — ТОЛЬКО расчёт│  │
                                      │  │ validator.py           │  │
                                      │  │ calculator.py           │  │
                                      │  │ (детерминированно,     │  │
                                      │  │  без AI, покрыто       │  │
                                      │  │  unit-тестами)         │  │
                                      │  └──────────────────────┘  │
                                      │  ┌──────────────────────┐  │
                                      │  │ ai/explainer.py        │  │
                                      │  │ получает ГОТОВЫЙ JSON  │  │
                                      │  │ с числами и только      │  │
                                      │  │ объясняет его текстом  │  │
                                      │  └──────────────────────┘  │
                                      └──────────────────────────┘
```

**Ключевой принцип:** `engine/` не делает ни одного обращения к LLM API — там
только чистые функции над числами. `ai/explainer.py`, наоборот, никогда не
считает и не придумывает цифры — он получает уже посчитанный JSON (Score, дельты
по районам, вклад каждой меры, сработавшие синергии) и переводит его в понятный
текст: сильные стороны, риски, рекомендации. Это разделение проверяемо прямо в
коде — в `engine/` нет ни одного импорта, связанного с AI.
## Структура репозитория

```text
Backend/
  data/
    districts.json       # 5 районов, 10 показателей, доли населения
    activities.json      # 14 мероприятий: стоимость, лаг и эффекты
    rules.json           # веса, синергии, несовместимости и бюджет
  engine/
    data_loader.py       # загрузка данных из JSON
    validator.py         # проверка правил сценария
    calculator.py        # расчёт Score по формуле из ТЗ
    calculator_test.py   # тесты контрольных значений
  ai/
    explainer.py         # объяснение расчёта через LLM или офлайн-fallback
  api/
    main.py              # FastAPI: /api/simulate и вспомогательные эндпоинты
  requirements.txt

Frontend/
  index.html             # экран выбора решений и результатов
  style.css
  app.js                 # бюджет, диаграммы, AI-объяснение, сравнение сценариев
```

## Как запустить локально

Все команды ниже выполняются из корня репозитория.

### 1. Backend

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его.

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
python -m pip install -r Backend/requirements.txt
```

Для AI-объяснений задайте `ANTHROPIC_API_KEY`. Без ключа приложение использует офлайн-fallback.

Linux/macOS:

```bash
export ANTHROPIC_API_KEY="ваш-ключ"
```

Windows PowerShell:

```powershell
$env:ANTHROPIC_API_KEY = "ваш-ключ"
```

Запустите API:

```bash
uvicorn Backend.api.main:app --reload --port 8000
```

API будет доступен по адресу `http://localhost:8000`. Документация Swagger: `http://localhost:8000/docs`.
