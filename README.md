# 🏙️ Аким на 5 часов

AI-симулятор управления городом: одинаковый виртуальный бюджет, пять управленческих
решений по транспорту, экологии, соцсфере, безопасности и городским сервисам —
и итоговый **Astana Quality of Life Score** с объяснением, что сработало и какие
риски остались.

## Проблема

Развитие города требует одновременного учёта нескольких направлений при ограниченном
бюджете. Симулятор даёт возможность быстро проиграть разные сценарии распределения
бюджета и увидеть их влияние на качество городской среды — без реальных последствий.

## Архитектура

```
┌──────────────┐      HTTP JSON      ┌──────────────────────────┐
│  Frontend     │ ──────────────────▶ │  FastAPI backend           │
│  (HTML/JS)    │ ◀────────────────── │                            │
└──────────────┘                     │  ┌──────────────────────┐  │
                                      │  │ engine/ — ТОЛЬКО расчёт│  │
                                      │  │ validator.py           │  │
                                      │  │ calculator.py           │  │
                                      │  │ (детерминированно,     │  │
                                      │  │  без AI, покрыто       │  │
                                      │  │  unit-тестами)         │  │
                                      │  └──────────────────────┘  │
                                      │  ┌──────────────────────┐  │
                                      │  │ ai/explainer.py        │  │
                                      │  │ получает ГОТОВЫЙ JSON  │  │
                                      │  │ с числами и только      │  │
                                      │  │ объясняет его текстом  │  │
                                      │  └──────────────────────┘  │
                                      └──────────────────────────┘
```

**Ключевой принцип:** `engine/` не делает ни одного обращения к LLM API — там
только чистые функции над числами. `ai/explainer.py`, наоборот, никогда не
считает и не придумывает цифры — он получает уже посчитанный JSON (Score, дельты
по районам, вклад каждой меры, сработавшие синергии) и переводит его в понятный
текст: сильные стороны, риски, рекомендации. Это разделение проверяемо прямо в
коде — в `engine/` нет ни одного импорта, связанного с AI.

## Структура репозитория

```
backend/
  data/
    districts.json     # 5 районов, 10 показателей, доля населения
    activities.json     # 14 мероприятий: стоимость, лаг, эффекты
    rules.json           # веса показателей, синергии, несовместимости, бюджет
  engine/
    data_loader.py        # чтение JSON, ничего не считает
    validator.py           # проверка правил сценария (бюджет, лимиты, конфликты)
    calculator.py           # расчёт Score по формуле из ТЗ
    calculator_test.py     # unit-тесты на контрольные значения
  ai/
    explainer.py            # объяснение готового расчёта через LLM (с офлайн-fallback)
  api/
    main.py                   # FastAPI: /api/simulate и вспомогательные эндпоинты
  requirements.txt
frontend/
  index.html                  # выбор 5 решений, live-бюджет
  style.css
  app.js                        # радар-диаграммы "до/после", AI-объяснение, сравнение сценариев
```

## Как запустить локально

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# (опционально) ключ для AI-объяснений через Claude — без него сработает офлайн-fallback
export ANTHROPIC_API_KEY=sk-ant-...

cd ..
uvicorn backend.api.main:app --reload --port 8000
```

API поднимется на `http://localhost:8000`. Документация Swagger — `http://localhost:8000/docs`.

### 2. Тесты движка (проверка контрольных значений из ТЗ)

```bash
cd backend
pytest engine/calculator_test.py -v
```

Ожидаемый результат — все тесты зелёные, в том числе:
- базовый Score без мероприятий = **52.56**
- пример из ТЗ (M7+M8+M10+M12+M5) = стоимость **95**, Score ≈ **56.5**, синергия M10+M12 срабатывает
- самый дешёвый валидный набор (M9+M11+M10+M12+M4) = стоимость **61**

### 3. Frontend

Простой статический сайт, не требует сборки:

```bash
cd frontend
python3 -m http.server 5500
```

Откройте `http://localhost:5500`. Backend должен быть запущен на порту 8000
(адрес задан в `app.js` через `API_BASE`, при необходимости поменяйте).

## Пример полного цикла

1. Выбираем 5 решений: **M7→Нура, M8→Нура, M10→Нура, M12 (город), M5→Сарыарка**.
2. Суммарная стоимость — **95 / 100**, бюджет не превышен.
3. Отправляем сценарий → получаем:
   - **Score = 56.54** (было 52.56 в базовом сценарии, +3.98)
   - сработала синергия **M10 + M12 → B1 +2 в Нуре**
   - слабейший район по-прежнему **Нура**, но его показатели выросли
   - AI-объяснение перечисляет, какие меры дали основной вклад, и советует,
     что добавить в следующей итерации (например, меру по транспорту в Нуре,
     раз направление осталось незатронутым)

## Что использует AI, а что — нет

| Компонент | Считает числа? | Использует LLM? |
|---|---|---|
| `engine/validator.py` | нет, только проверяет правила | нет |
| `engine/calculator.py` | да, по формуле из ТЗ | нет |
| `ai/explainer.py` | нет, только объясняет готовый JSON | да (с офлайн-fallback без ключа) |

## Что можно развить дальше

- Сравнение сценариев нескольких команд на одном экране (сейчас — сравнение
  сценариев одного пользователя в рамках сессии).
- Моделирование случайных городских событий (авария на теплотрассе, резкий
  скачок пробок), требующих перераспределения оставшегося бюджета.
- Автогенерация краткой презентации сценария (PDF/слайды) на основе того же
  JSON, который уже получает `explainer.py`.
- Подключение реальных открытых данных города вместо синтетического датасета —
  архитектура это уже позволяет, достаточно заменить `districts.json`.
